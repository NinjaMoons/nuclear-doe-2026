## Гипотеза (зарегистрирована до проверки)
`L = R3 + λ·L_con`, где `L_con` = InfoNCE (τ = 0.1) по Pearson в радиальной полосе:
- позитив: `corr(BP(A_k/max), BP(T_k))`;
- hard negatives: `corr(BP(A_k/max), BP(N_kj))`, где `N_kj` = T_j, пересэмплированная на физическую сетку плоскости k (масштаб z_k/z_j, Test 2);
- пары с `|corr(BP T_k, BP N_kj)| ≥ 0.3` исключены (группа A: остаётся 22 % пар, группа B: 97 %).

Код: `xplane/loss.py`, тесты `xplane/test_loss.py` (4/4: конечность на чёрных и константных целях, монотонность по ghost, инвариантность к яркости, исключение коррелированных пар).

**Отличие от R3/R8/R18/STACK.** R3 оптимизирует только «свою» плоскость. R8 и R18 — архитектурные головы. STACK — их сумма. R15 штрафовал осевую innovation без hard negatives и без физического масштаба. R20 — первый член, явно штрафующий сходство с **физически выровненными чужими целями**.

## Предпроверка (до GPU, по заранее заданному критерию)
**Постановка.** Adam по фазе на каждом квартете. Старт с экспорта V2. 300 шагов, lr 0.05. 8 TRAIN-B квартетов: B64:010, B208:006, B208:127/119/193/046/041/090.

**Сравнение.** Арм R3 против R3 + λ·L_con. λ задан правилом `λ·L_con(init) = f·R3(init)`.

**Метрика.** Official export → PNG → P / SSIM / own / inter-z по полосам.

**Критерий GO.** Ghosting ↓ **без** падения P и SSIM. Это верхняя граница того, что может дать член loss: если per-sample оптимум платит метрикой, амортизированная сеть тоже заплатит.

## Вывод
1. **Член работает, как задуман.** Ghosting снижается монотонно по λ: inter-z до −.044 (8/8), own +0.5 из 4.
2. **Но он двигает решение вдоль фронта метрика ↔ разделение, а не расширяет фронт.** SSIM падает при каждой дозе (6–8/8). P падает при f ≥ .10. При f = .05 P нейтрален, а SSIM всё равно −.003.
3. **Сигнал разделения уже в R3.** Без L_con R3 сам снижает L_con на 70–80 %. Это согласуется с нейтральным R15.
4. **Ожидаемое изменение официальных P/SSIM при амортизированном обучении ≤ 0.** Обучение на GPU ради визуального снижения ghosting ценой метрики противоречит гейту.

**SCIENCE_GATE = NO_GO** (техническая причина: компромисс P/SSIM ↔ разделение на per-sample оптимуме, 8/8 квартетов). READY-карточки в #51 нет.
