# doe_core/fresnel.py — одношаговый Fresnel (Issue #14)

Статус: реализация по **предложенному** контракту v1.1-amplitude (`docs/INTERFACES_V1.md`, PR #15); API Fresnel в v1.1 не менялся. Формула — слайд 2 официальной презентации (`docs/spec/AI-photonics-case.pdf`, SHA256 `a2e4ded9…6422a`), параметры — слайд 5. ASM (`doe_core/asm.py`, #2) — отдельный оператор, здесь не вызывается.

## API

```python
from doe_core.contracts_v1 import CaseConfigV1, FresnelGeometry
from doe_core.fresnel import propagate_fresnel, sampling_report

case = CaseConfigV1()
field = torch.polar(torch.ones_like(phase), phase)       # phase [B,1,128,128], рад; A = 1
planes = [propagate_fresnel(field, case.plane(i)) for i in range(4)]   # одна и та же маска
intensity = planes[0].field.abs() ** 2                  # сырая, без нормировки
dy_out, dx_out = planes[0].output_pitch_m               # метры, зависят от z
```

- `field`: complex64/complex128 `[B,1,H,W]`, B>=1, H,W>=2, конечные значения. Результат `FresnelField`: `field` той же формы/dtype/device, `output_pitch_m=(dy_out, dx_out)`, `distance_m`. Autograd по полю сохраняется.
- Ошибки входа (не Tensor, не комплексный dtype, неверная форма, NaN/Inf, `geometry` не `FresnelGeometry`) — `ValueError`. z<=0 отклоняет сам `FresnelGeometry`: при z=0 оператор сингулярен (множитель 1/z, `dx_out=0`), тождеством он не является.
- `sampling_report(H, W, geometry)` — диагностика дискретизации одной плоскости (см. ниже), только числа.

## Формула и дискретизация

Слайд 2 (j = i):

```
K(x,y) = exp(ikz)/(iλz) · exp(iπ(x²+y²)/(λz)) · FFT{ H(u,v) · exp(iπ(u²+v²)/(λz)) },   k = 2π/λ
```

Дискретно (соглашение команды, контракт v1):

```
u = (n − W//2)·dx,   v = (m − H//2)·dy                 вход, n = 0..W−1, m = 0..H−1
x = (q − W//2)·dx_o, y = (p − H//2)·dy_o               выход
dx_o = λz/(W·dx),    dy_o = λz/(H·dy)
F    = fftshift(fft2(ifftshift(U·chirp_in), norm="ortho"))        знак Фурье отрицательный
Uout = exp(i2πz/λ)/(iλz) · chirp_out · sqrt(H·W)·dy·dx · F
```

`sqrt(H·W)·F` с `norm="ortho"` — ненормированная DFT, а `dy·dx` — площадь пикселя в интегральной сумме. Итог — ровно дискретная сумма Френеля в форме свёртки:

```
Uout(y_p, x_q) = exp(ikz)/(iλz) · Σ_{m,n} U(v_m, u_n) · exp(iπ((x_q−u_n)² + (y_p−v_m)²)/(λz)) · dy·dx
```

потому что `x_q·u_n/(λz) = (q−W/2)(n−W/2)/W`. На этом основан главный тест.

Единицы: все длины в метрах, фаза в радианах. Ровно один `fft2` на вызов (на плоскость). Нет padding, crop, ресэмплинга, bandlimit и нормировки. Множители `chirp_in`, `chirp_out` и несущая `exp(ikz)` (≈ 3e5 рад) строятся в float64 на CPU при каждом вызове (кэша нет, inference-safe), затем приводятся к dtype/device поля.

Баланс мощности с площадями пикселей: `Σ|Uout|²·dy_o·dx_o = Σ|U|²·dy·dx` (тест, отн. ошибка ≤ 4e-16). Голые суммы не равны.

**Модуль |U| и интенсивность |U|² (контракт v1.1-amplitude).** `propagate_fresnel` возвращает комплексное поле; ни модуль, ни интенсивность внутри не считаются и не нормируются. По текстовому ТЗ (раздел 2) основная наблюдаемая величина — модуль `|U|`. Её даёт общая операция `doe_core.observables.field_observables(U).amplitude`; интенсивность `|U|²` — диагностика и энергетика. Градиент `|U|` по фазе проверен против прямой суммы и конечен при нулевом поле. Физическая проверка на четырёх плоскостях и воспроизводимый пример — [fresnel_validation.md](fresnel_validation.md).

## Дискретизация и ограничения модели

**Входной chirp.** `exp(iπu²/(λz))` дискретизирован без алиасинга, если прирост фазы между соседними пикселями < π, т. е. при `z > (2·(N//2)−1)·dx²/λ ≈ N·dx²/λ = 24.06 мм`. Минимальное z кейса 24.1 мм — **на самой границе** (0.9905π). Это обязательное условие: при меньших z (например, 20 мм — тест) FFT-вход алиасирован.

**Выходной chirp** при z ≥ 25.3 мм недодискретизирован (до 1.14π). Он меняет только фазу выходного поля, поэтому на интенсивность (PNG, Pearson/SSIM) не влияет. Если кто-то использует комплексную фазу выходного поля между пикселями — учитывать.

**Параксиальная оценка** `π·r⁴/(4λz³)` (r — наибольшее расстояние между пикселями входа и выхода, угол к углу) ≈ 1 рад. Это консервативная верхняя граница отброшенного члена, не ошибка. Классический критерий «≪ 1» формально не выполнен для крайних пар пикселей.

**Главное ограничение: окно выхода и полноапертурные маски.** Выходное окно single-FFT Fresnel — `λz/dx` ≈ 1.28–1.47 мм, т. е. почти совпадает с размером ДОЭ (1.28 мм). Дискретная сумма оставляет всю мощность в этом окне. Физически свет, отклонённый ДОЭ дальше (до λ/(2dx) ≈ 26.6 мрад, т. е. ±0.64 мм за край на 24 мм), уходит. В модели он «заворачивается» в окно, потому что ядро `exp(iπ(x−u)²/(λz))` недодискретизировано при `|x−u| > λz/(2dx)`.

Сравнение с ASM (`doe_core/asm.py`, без параксиального приближения, pad 4/8 со сходимостью) при z = N·dx²/λ = 24.06 мм, где сетки совпадают (`dx_o = dx`):

| вход | интенсивность Fresnel vs ASM, отн. L2 | доля мощности ASM в окне 1.28 мм |
|---|---|---|
| гаусс w0 = 150 мкм (тест) | комплексное поле: 7.2e-8 | ≈ 1 |
| сглаженная случайная фаза (гаусс-размытие 4 px, ×8), A=1 | 0.28 | 0.947 |
| случайная фаза U(−π, π), A=1 | 1.1 | 0.567 |

Вывод: для гладких локализованных полей оператор совпадает с физикой до 1e-7. Для DOE-подобных масок с широким угловым спектром официальный дискретный оператор заметно отличается от непрерывной дифракции. Это свойство метода, заданного ТЗ (слайды 2, 5), а не ошибка кода. Синтез и оценку кейса нужно вести этим оператором, а заявления о «физическом» восстановлении на реальном ПВМС не делать без отдельной проверки. Сравнение выполнено скриптом на основе тестовых фикстур (не в CI); при изменении маски цифры меняются.

## Что не сделано

- Сравнение с внешней реализацией (waveprop `fresnel_one_step`, SHA 84c3e7dd) не выполнено: нужна согласованная координатором проверочная среда. Прямая сумма, замкнутые формулы и ASM — независимые эталоны, но написаны тем же автором.
- Fresnel vs Rayleigh–Sommerfeld для конкурсных z на сетке кейса не делалось (сетки не совпадают при z ≠ 24.06 мм; нужна интерполяция).
- CUDA не проверялась. Пиксельная апертура ПВМС (fill factor, sinc-огибающая) не моделируется.
- Совпадение с собственными тестами не доказывает физическую точность для произвольных масок — см. раздел об окне выхода.
