# Физическая валидация Fresnel (#14B)

Статус: черновик к контракту **v1.1-amplitude** (PR #15). Основная наблюдаемая величина — амплитуда `|U|` через `doe_core.observables.field_observables`; интенсивность `|U|²` — только диагностика и энергетика. Оператор `propagate_fresnel` по-прежнему возвращает комплексное `U` и ничего не нормирует. Модуль и тесты оператора — в [fresnel.md](fresnel.md).

## Воспроизводимый пример: одна фаза → четыре амплитуды

Фаза — суперпозиция четырёх тонких линз, по одной на плоскость: линза k фокусирует равномерную волну (A=1) в точку `(y_k, x_k)` на расстоянии `z_k`, а в DOE остаётся только `angle(Σ_k)`. Ожидаемый результат следует из оптики, а не из кода: в каждой плоскости `k` — яркое пятно в своей точке, в пикселе `round(x_k / dx_out_k) + 64`.

```python
# python -I docs_example.py  (из корня репозитория; numpy, torch, pillow из requirements)
import hashlib, math, pathlib
import numpy as np, torch
from PIL import Image
from doe_core.contracts_v1 import CaseConfigV1
from doe_core.fresnel import propagate_fresnel
from doe_core.observables import field_observables

case, n = CaseConfigV1(), 128
foci = ((0.2e-3, 0.2e-3), (0.2e-3, -0.2e-3), (-0.2e-3, -0.2e-3), (-0.2e-3, 0.2e-3))  # (y, x), м
v = (torch.arange(n, dtype=torch.float64) - n // 2)[:, None] * case.input_pitch_m[0]
u = (torch.arange(n, dtype=torch.float64) - n // 2)[None, :] * case.input_pitch_m[1]
total = sum(torch.polar(torch.ones(n, n, dtype=torch.float64),
                        -math.pi * ((u - x0) ** 2 + (v - y0) ** 2) / (case.wavelength_m * z0))
            for (y0, x0), z0 in zip(foci, case.distances_m))
phase = torch.angle(total)[None, None]                 # одна фаза [1,1,128,128], рад, [-pi, pi]
field = torch.polar(torch.ones_like(phase), phase)     # A = 1

out_dir = pathlib.Path("artifacts/fresnel_example"); out_dir.mkdir(parents=True, exist_ok=True)
arrays = {"phase_rad": phase.numpy()[0, 0]}
for k in range(4):
    out = propagate_fresnel(field, case.plane(k))      # одно и то же поле на всех z
    amp = field_observables(out.field).amplitude[0, 0]
    arrays[f"amplitude_{k + 1}"] = amp.numpy()
    ratio = amp.numpy() / amp.max().item()                                    # float64, сначала деление (c8f9a43)
    q = np.floor(255 * ratio + 0.5).astype(np.uint8)                         # иллюстрация policy v1.1
    Image.fromarray(q, mode="L").save(out_dir / f"reconstructed_{k + 1:02d}.png")
    peak = divmod(int(amp.argmax()), n)
    print(f"z={out.distance_m*1e3:.1f} mm pitch={out.output_pitch_m[1]*1e6:.7f} um "
          f"peak={peak} max={amp.max().item():.4f} sha256={hashlib.sha256(amp.numpy().tobytes()).hexdigest()[:16]}")
np.savez(out_dir / "fresnel_example.npz", **arrays)    # без pickle; artifacts/ в .gitignore
```

|---|---|---|---|---|---|---|
| 24.1 | 10.0165625 | (84, 84) | (84, 84) | 56.8914 | 3.90 | `163e18a5d557d8e2` |
| 25.3 | 10.5153125 | (83, 45) | (83, 45) | 54.0113 | 3.76 | `7c58cc9b6fe1edc2` |
| 26.5 | 11.0140625 | (46, 46) | (46, 46) | 48.2666 | 3.24 | `bdb294a28c289d01` |
| 27.7 | 11.5128125 | (47, 81) | (47, 81) | 31.6256 | 2.45 | `457442f364c5a2de` |

SHA256 побайтно воспроизводятся при повторном запуске на той же платформе. FFT-бэкенды других ОС/CPU могут отличаться в младших битах, поэтому для сравнения между машинами используйте пики и max A (до 1e-12).

Все четыре пятна — глобальные максимумы своих плоскостей, точно в предсказанных пикселях. Если взять для плоскости 27.7 мм pitch плоскости 24.1 мм, ожидаемая точка сдвигается на ~2.6 px. Поэтому PNG разных плоскостей — разные физические окна (1.28–1.47 мм), а не общая сетка 10 мкм. Контраст (3.90 → 2.45) убывает с z — это измеренный результат для **этой** маски, причина не установлена. Объяснение «дальние линзы сильнее недодискретизированы» неверно (ревью PR #18): локальная частота края линзы `|u − x_k|/(λz_k)` при том же смещении и апертуре убывает с z — 65.5 цикл/мм на 24.1 мм против 57.0 на 27.7 мм при Найквисте 50. Все четыре линзы частично алиасированы на краях, и сильнее всего ближняя. Соседние плоскости отстоят всего на 1.2 мм, поэтому чужие линзы расфокусированы слабо. PNG здесь — иллюстрация формулы policy `per_plane_max_amplitude_round_half_up_u8_v1_1` в точном порядке контракта `c8f9a43`: `ratio = A/max(A)` в float64, затем `floor(255·ratio + 0.5)`. Обратный порядок `255·A/max(A)` может дать соседний код (контрпример 105 против 106 из ревью #15). Официальный экспорт — модули #4/#7.

Тесты: `tests/core/test_fresnel_physical.py` — положения четырёх фокусов и контраст > 2, неверный pitch даёт неверное положение, баланс мощности с площадями пикселей для каждой плоскости (rel 1e-12), `intensity == amplitude²`, градиент амплитуды в фокусе каждой плоскости по общей фазе конечен, ненулевой и различен для разных плоскостей, complex64 vs complex128 амплитуды < 1e-5. Мутации: неверный знак Фурье, сопряжённые chirp и полупиксельный центр ломают эти тесты. Перестановку выходных pitch на квадратной сетке они не видят — её ловят прямоугольные тесты `test_fresnel.py`.

## Проверка экспортированного DOE (подготовка к READY NEXT)

`check_decoded_doe(phase)` в `tests/core/test_fresnel_physical.py` проверяет любую **уже декодированную** фазу DOE `[1,1,128,128]` (рад, `[−π, π]`) на четырёх плоскостях при A=1:
- конечные ненулевые амплитуды `|U|`;
- нативные pitch плоскостей;
- мощность с площадями пикселей (< 1e-12);
- комплексное поле против независимой сепарабельной прямой суммы без FFT (< 1e-11).

PNG здесь не декодируются, codec/метрики не копируются: фазу даёт экспорт #7.

```bash
FRESNEL_DECODED_PHASE=<decoded_phase.npy | .npz с ключом phase_rad> \
  python -m pytest tests/core/test_fresnel_physical.py -k exported -s
```

Без переменной тест пропускается: это необязательная авторская проверка, а не обязательный gate координатора. Самопроверка на файле из примера выше (`fresnel_example.npz`): прямая сумма 2.4e-14…2.6e-14, мощность ≤ 4.4e-16, `max A` совпадает с таблицей примера.

**Протокол для настоящего DOE (этап C).** Тот же запуск выполняет `physical_report_for_doe(phase)`:
1. SHA256 файла артефакта.
2. Точные инварианты `check_decoded_doe` с порогами — нарушение означает ошибку данных или оператора.
3. Диагностика без порогов на каждой плоскости: положение пика, доля тёмных пикселей (< 1e-3 максимума), сравнение с непрерывной моделью пиксельного ПВМС — отн. L2 `|U|`, формы `|U|/max` и доля мощности в окне.

Результаты для первого настоящего артефакта будут добавлены сюда с SHA файла, commit экспорта и командой. Пробный прогон на `fresnel_example.npz`: пики (84,84)/(83,45)/(46,46)/(47,81), тёмных пикселей 1.5–3.8%, пиксельный ПВМС: `|U|` 0.42–0.44, форма 0.23–0.25, мощность в окне 0.552–0.560.

## Модель против непрерывной дифракции

Single-FFT оператор совпадает с независимой прямой суммой и внешним reference (waveprop `fresnel_one_step`, проверка координатора ≤ 5.8e-11) — это подтверждает **заданный дискретный оператор**. С непрерывной физикой он совпадает только для полей, свет которых остаётся в окне `λz/dx`. Сравнение с ASM (`doe_core/asm.py`, PR #13; без параксиального приближения, сходимость по padding) при z = N·dx²/λ = 24.06 мм, где сетки совпадают:

| вход (A=1, 128×128, 10 мкм) | отн. L2 интенсивности Fresnel vs ASM | доля мощности ASM в окне 1.28 мм |
|---|---|---|
| гауссов пучок w0 = 150 мкм | 7.2e-8 (комплексное поле) | ≈ 1 |
| сглаженная случайная фаза (размытие 4 px, ×8) | 0.28 | 0.947 |
| случайная фаза U(−π, π) | 1.1 | 0.567 |

Независимые оценки координатора (R-002-E12/E13, [отчёт](https://github.com/NinjaMoons/nuclear-doe-2026/blob/387b751df5afe6299030ac3bdb3574cce25e6649/docs/research/reviews/R-002-cycle02-experiments.md)) подтверждают то же. FFT совпадает с той же дискретной суммой до ≤ 1.85e-14. При этом ошибка интенсивности против непрерывного reference (антипроизводные C/S, midpoint-refinement) — 1.8–2.3% для постоянной апертуры и 79–82% для наклона 45/мм; refinement 32 подточками снижает её до ~1.5–1.9e-5. Сравнение с моделью прямоугольного пикселя (point vs cell) — только диагностика: порог 5%, центральный crop и pixel-хуки в CI не вводятся, обязательный 128×128 one-FFT forward не меняется.

Вывод: синтез и оценка кейса корректны относительно оператора из ТЗ (слайды 2, 5). Заявления о восстановлении на реальном ПВМС требуют отдельной проверки: окно, пиксельная апертура, RS/непараксиальность, стенд. Это ограничение модели, а не дефект кода.

Колонки:
- **Прямая сумма** — отн. L2 комплексного поля против независимой сепарабельной суммы без FFT.
- **Квантование** — отн. L2 `|U|` после универсального равномерного квантователя фазы на L уровней. Это **не** codec проекта (тот — #7, 255 шагов): исследуется чувствительность, а не экспорт.
- **∇ f32↔f64** — отн. L2 градиента нейтрального функционала Σ_k Σ w·|U_k|² (или |U_k|) по общей фазе.
- **Тёмные пиксели** — доля |U| < 1e-3·max.
- **Пикс. ПВМС** — независимый эталон: непрерывный интеграл Френеля для ПВМС с прямоугольными пикселями 100% заполнения, квадратура Гаусса–Лежандра по ячейке, те же выходные точки. Для любой маски он точно равен `K_y·exp(iφ)·K_xᵀ`, потому что пропускание в ячейке постоянно, а ядро сепарабельно.

Проверки самого эталона:
- сходимость по квадратуре: 16 против 32 узлов < 1e-6;
- 2D-форма совпадает с произведением 1D-интегралов (< 1e-12) для сепарабельных масок;
- с одним узлом в центре ячейки эталон равен production-оператору (< 1e-12);
- для π-шахматки доля мощности в окне 0.165–0.166 против аналитических sinc(½)⁴ = 0.164.

Точные инварианты (тесты `test_family_invariants`, без порогов качества):
- конечность;
- мощность с площадями пикселей < 1e-12;
- прямая сумма < 1e-11;
- нативные pitch;
- конечные градиенты;
- ∇|U|² в f32 согласован с f64 до < 1e-5.

Положения: линза f = 25.3 мм фокусирует на оси на 25.3 мм; линза + наклон — в `round(λ·f·f_i/pitch_out) + 64` = (51, 83). Пороги aliasing и обрезание изображения **не вводятся**.

Иллюстрации: `FRESNEL_FIGURES=artifacts/fresnel_validation python -m pytest tests/core/test_fresnel_physical.py -k figures -s`. Четыре монтажа (мультифокус, линза+наклон, решётка 3 px, шахматка π): фаза и |U| на 4z; верхний ряд — single-FFT модель, нижний — пиксельный ПВМС. PNG не коммитятся (`artifacts/` в `.gitignore`).

## Научные выводы для защиты (этап D)

**Подтверждено численно:**
- Реализован ровно оператор слайда 2 в дискретизации контракта v1.1. Независимая прямая сумма: ≤ 4.6e-14 на 11 семействах × 4z. Внешний waveprop `fresnel_one_step` (проверка координатора): ≤ 5.8e-11. Конечные разности: 5.9e-9.
- Энергетика с площадями пикселей ≤ 1e-12. Выходные сетки 10.017–11.513 мкм, у каждой плоскости своя.
- Для гладких локализованных полей дискретная модель совпадает с непрерывной: гауссов пучок против замкнутой формулы ≤ 1.3e-8, против ASM без параксиального приближения 7e-8.
- Градиенты по общей фазе конечны для всех семейств. Функционал |U|² устойчив в float32 (≤ 4.4e-7 к float64).
- Чувствительность к квантованию фазы почти не зависит от маски и ~1/L: ≈ 0.5% амплитуды при 256 уровнях, ≈ 2% при 64, 6–11% при 16.

**Ограничения модели:**
- **Точечные пиксели.** Оператор кейса считает ПВМС набором точек. Пиксель конечного размера отправляет часть света в высшие порядки дифракции за окном `λz/dx`. В окне остаётся 43–79% мощности точечной модели: 17% на Найквисте, ~60% у линз, 50% у решётки 3 px. Форма |U|/max отличается на 6–41% в зависимости от маски. Простой огибающей sinc это не компенсируется: внутри ячейки на краях окна меняется фаза ядра.
- **Окно ≈ апертура.** Окно `λz/dx` = 1.28–1.47 мм почти равно размеру ДОЭ. Свет, отклонённый дальше, дискретная модель заворачивает обратно: чистый наклон без линзы даёт сдвинутую «тень» апертуры, перенесённую через край окна.
- **Шаг chirp** (24.06 мм против z_min 24.1 мм) — необходимое условие только для самого chirp, а не pass/fail для произведения поля на chirp (R-002-E12).
- **Амплитудный loss v1.1** негладок в U = 0: где много тёмных пикселей (линзы — до 100%), градиент |U| в float32 отличается от float64 до 100%. В |U|² этого нет. Это касается обучения (#3/#5), а не propagator; регуляризация `sqrt(I + ε)` с ε = 1e-6·⟨I⟩ снизила расхождение у линзы до 2.7e-4 (диагностика, не рекомендация policy).
- Скалярная параксиальная модель, A = 1, без поляризации, fill factor, межпиксельных перекрёстных помех и реального профиля пучка.

**Не проверялось экспериментально:** реального ПВМС, лазера, камеры и стенда не было. Не моделировались fill factor < 100%, фазовая нелинейность и LUT модулятора, межпиксельные помехи (fringing), неравномерность засветки, юстировка. Fresnel vs Rayleigh–Sommerfeld на z 25.3–27.7 мм не сравнивался. CUDA не проверялась.

**Почему результаты не доказывают точность реального SLM:**
1. Все проверки сравнивают модели между собой (дискретная, непрерывная пиксельная, ASM, аналитика) в общем скалярном приближении, без измерений.
2. Даже идеализированный пиксельный ПВМС отличается от модели кейса на десятки процентов для DOE-подобных масок.
3. Метрики кейса считаются по оператору кейса. Высокие Pearson/SSIM подтверждают качество синтеза **относительно этого оператора**, а не изображение на стенде.

## Не сделано

- Fresnel vs RS/ASM на конкурсных z 25.3–27.7 мм — сетки не совпадают, нужна интерполяция.
- Пиксельная апертура/fill factor ПВМС, CUDA, реальный стенд.
- Приёмка обученной сети и E2E-gate — зона #3/#4/#5/#7.
