# Научный процесс: координатор + два Gemini

Создано 2026-11-06. Репозиторий: NinjaMoons/nuclear-doe-2026. Цель — переиспользовать проверенные научные реализации нейросетевого синтеза ДОЭ в срок хакатона.

## Пакет готов; запуск ожидает команды Павла

После явной команды Павла на выполнение:

1. Павел отправляет **только** [R-001-A](prompts/R-001-A-engine-audit.md) Gemini A.
2. Одновременно в отдельном чистом чате отправляет **только** [R-001-B](prompts/R-001-B-independent-review.md) Gemini B. Не прикладывать ответ A, этот README, findings или decisions: они раскрывают предпочтение координатора.
3. Возвращает координатору полные ответы с обозначением `R-001 / Gemini A` и `R-001 / Gemini B`, включая ссылки, код, оговорки и сообщения о неудачных проверках. Если ответ разбит на части — дождаться всех частей.
4. Координатор сохраняет ответы в `responses/R-001-A-01.md` и `responses/R-001-B-01.md`; исходный текст не исправляет. Модель/версия, время, доступ к вебу и реальное выполнение кода фиксируются как сообщённые данные; неизвестное остаётся неизвестным.
5. По каждому значимому тезису проверяет первоисточник и соответствие тезису, версию/API, зависимости, лицензию кода/весов/данных, применимость, оценку интеграции и минимальный тест. Затем обновляет [findings](findings.md), [decisions](decisions.md) и [backlog](backlog.md).
6. Подтверждённое ограниченное действие передаёт разработчикам через GitHub Issue; перед созданием ищет дубли. Вопросы о качестве/скорости закрывает только после эксперимента с артефактами.

Присланный до запуска процесса [ответ Gemini](responses/R-001-initial-gemini.md) сохранён целиком. Его авторство A/B и версия модели неизвестны; это не независимая рецензия. [Первичная проверка](reviews/R-001-initial-review.md) уже выполнена по источникам, без вычислительного эксперимента.

## Роли и независимость

- **Координатор:** постановка узкого вопроса, проверка доказательств, решения, GitHub и контроль времени.
- **Gemini A:** библиотеки, API, лицензии, переиспользование, стоимость интеграции, воспроизводимый пример.
- **Gemini B:** независимые критерии физической корректности, отрицательные тесты, уязвимости в оценке. В R-001 это отдельная работа, не повтор обзора A.
- **Павел:** передача промптов/полных ответов между системами. Автоматический API Gemini не настроен и для процесса не требуется.

Для критического предложения после первого ответа A координатор готовит B нейтральную карточку: точный метод/код, геометрия, проверяемые утверждения и первичные источники. Удаляет автора, ранжирование и рекомендацию A. B сначала пишет собственный вердикт; сопоставление проводится после его получения. Фиксировать, что B видел: независимость по предпочтению не означает незнакомство с методом. Повторять исследование только при новом свидетельстве, проваленном тесте или существенном противоречии.

## Реестры и статусы

- [backlog.md](backlog.md): задачи R-001, R-002, …; приоритет, один вопрос, выход, зависимость и состояние.
- [findings.md](findings.md): атомарные утверждения с ID `R-001-C01`, источником, версией, областью применимости, статусом и тестом.
- [decisions.md](decisions.md): решение, основание, последствия, условие отмены; решение не превращает гипотезу в факт.
- [sources.md](sources.md): первичные ссылки и проверенные версии.
- [test-plan.md](test-plan.md): предлагаемые воспроизводимые проверки и критерии.

| Статус утверждения | Значение |
| --- | --- |
| CONFIRMED | Конкретный тезис подтверждён проверенным первоисточником, выводом с явными допущениями или воспроизводимым тестом. Указать, чем именно. |
| PLAUSIBLE | Правдоподобно, но доказательств пока недостаточно. |
| REJECTED | В исходной формулировке неверно либо неприменимо; записать причину и корректную замену. |
| NEEDS_TEST | Нужен вычислительный эксперимент; до него нельзя заявлять результат. |

Состояние задачи (`READY / IN_PROGRESS / WAITING_GEMINI / WAITING_TEST / DONE / DEFERRED`) отдельно от достоверности тезисов. R-001 не завершён до выбора на основе тестов.

## Короткий цикл и передача разработчикам

Ориентир: один вопрос и 20–30 минут на исследование, 10–15 минут на проверку источников, до 60–90 минут на ограниченный инженерный spike. Это плановые пределы, не измеренные сроки. По исчерпании бюджета записать неопределённость и продолжать разработку по последнему проверенному варианту. Новая библиотека подключается через минимальный адаптер; работающий код не переписывается ради архитектуры Gemini.

Полное ТЗ, физические параметры, GPU и точный срок кейса пока не установлены. В локальном пакете координации рабочая граница — **2026-11-07 21:00 Europe/Moscow**, но это не подтверждённый дедлайн конкретного кейса. Не выдавать пример геометрии за ТЗ. Исследование не блокирует доступные задачи; Adam/GS — baselines, а выполнение требования нейросетевого синтеза проверяется отдельно по ТЗ.

Issue содержит: R-ID и claim-ID; конкретное действие; существующий интерфейс и границы файлов; первичные источники и лицензии; AC с командами/артефактами; ожидаемый бюджет и stop condition. `PLAUSIBLE` передаётся только как исследовательский spike, без обещания качества. `REJECTED` не становится заданием на реализацию.

После **каждого** полного ответа Gemini координатор выдаёт ровно эти шесть пунктов:

1. Краткий вывод.
2. Оценка достоверности с claim-ID.
3. Что использовать в проекте.
4. Что отклонить.
5. Нужны ли изменения в GitHub: конкретные файлы/Issue или «нет».
6. Следующий промпт Gemini: ссылка и адресат, либо явно «цикл закрыт, нового исследования не требуется».
