# R-001 / Gemini A — аудит физического движка

Ты — научный исследователь проекта Nuclear IT Hack. Отвечай по-русски. Не считай собственный ответ источником доказательств.

## Один вопрос

**Какой из готовых движков TorchOptics или waveprop следует первым подключить для дифференцируемого фазового синтеза ДОЭ, чтобы минимизировать риск интеграции при ограниченном времени хакатона?**

## Ограничения проекта

- Целевой репозиторий: NinjaMoons/nuclear-doe-2026. Если приватный репозиторий недоступен — прямо скажи; не выдумывай его содержимое. При последнем подтверждённом осмотре там был только README; состав мог измениться.
- Направление — Python/PyTorch, complex поля и градиент по real фазе. CPU-путь обязателен для разработки; наличие GPU/CUDA и точные версии целевой среды неизвестны.
- Полное ТЗ, длина волны, шаг, дистанция, апертура и допуски пока неизвестны. Пример 532 нм / 8 мкм / 25 мм / 256² — только пример, не заданная геометрия.
- Плановый бюджет первичного spike 60–90 минут. Рабочая граница из пакета координации — 7 ноября 2026 21:00 МСК, срок конкретного кейса не подтверждён. Не обещай время обучения/скорость без логов.
- Сохранять работающий код и принятые интерфейсы. Нужен тонкий адаптер, без собственного нового ASM и архитектурной переработки.
- Не исследовать HoloNet/U-Net/веса в этом ответе: это следующий цикл. Независимые физические тесты разрабатывает другой исследователь; здесь нужен твой минимальный технический MRE.
- На 6 ноября 2026 метаданные PyPI: torchoptics 1.0.2, waveprop 0.0.12. Перепроверь. Не смешивай API main и установленного release.

## Первичные источники обязательны

Используй исходный код, официальные docs/PyPI, LICENSE и статьи авторов; для каждого существенного утверждения дай точную ссылку, версию/commit, имя файла/символа и что именно источник подтверждает. Не приписывай лицензии коду по статье. Отдельно проверь транзитивные зависимости. Если нет веба или возможности запуска — сообщи это, не имитируй проверку.

Стартовые репозитории:
- https://github.com/MatthewFilipovich/torchoptics
- https://github.com/ebezzam/waveprop
- Matsushima & Shimobaba (2009), DOI 10.1364/OE.17.019662 — при утверждениях про band-limiting и sampling.

## Формат ответа

1. Доступные инструменты и фактически выполненные действия: веб/чтение/установка/запуск. Невыполненное назвать явно.
2. Таблица **двух** кандидатов: версия/commit; публичный вызов и сигнатура; input/output shape и dtype/device; autograd; ASM/BLAS; точная семантика padding/crop; лицензия и условия атрибуции; зависимости; ограничения совместимости. Статус каждого тезиса CONFIRMED / PLAUSIBLE / REJECTED / NEEDS_TEST.
3. Самодостаточный минимальный Python-пример и команды для изолированной CPU-среды: complex поле -> применение real фазы -> propagation -> интенсивность -> scalar loss -> backward. Выведи версии, shape, finite и норму градиента. Вход воспроизводим по seed; нормировка не маскирует потери энергии. Укажи, запускал ли код; если да — полный stdout и оборудование.
4. Рекомендация одного первого кандидата, причины отказа от другого как первого и явные условия переключения. Раздели время установки, адаптера и научной приёмки; оценки обозначь как оценки.
5. Короткий текст инженерной Issue: действие, границы файлов/интерфейса без предположений о приватном коде, AC, команда MRE, артефакты, риск и stop condition.

## Критерий полезности

Разработчик может проверить импорт и градиент на указанном release и понять объём адаптера; все важные утверждения прослеживаются до первоисточников. Вывод без точного API, лицензии и воспроизводимого MRE недостаточен. Непроверенное качество/совместимость остаётся NEEDS_TEST, даже если библиотека популярна.
