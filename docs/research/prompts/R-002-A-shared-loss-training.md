# R-002-A / Gemini A — один loss для общей фазы

## Один вопрос
Достаточно ли предложенного в контракте v1 общего loss mean((I_p/max(I_p)-T_p)^2) для короткого physics-guided обучения four-targets -> one-phase без фазовых labels, и какой минимальный тест выявит его существенные недостатки?

## Данные и границы
ТЗ: 4 grayscale PNG8 128×128 -> одна phi 128×128 в [-pi,pi], lambda=532 нм, входной шаг 10 мкм, z=24.1/25.3/26.5/27.7 мм. Обязателен одношаговый Fresnel FFT с input/output chirps, exp(ikz)/(i lambda z) и площадью входного пикселя. Каждый z получает одно и то же U0=A*exp(i*phi). Выходной шаг lambda*z/(128*10 мкм): 10.0165625/10.5153125/11.0140625/11.5128125 мкм. Метрики ТЗ — Pearson и SSIM для каждой пары; точная PNG/preprocessing политика ещё не согласована. Нейросеть обязательна, Adam — comparison, а не замена нейрометода.

Уже предложен командой v1 в PR #15 (не считать согласованным): A=1, T=PNG/255, равные веса 1/4, per-plane max display, loss MSE по этому display; нулевая prediction — ошибка; evaluate ничего не нормирует. Primary Pearson/SSIM — после сохранения/повторного чтения DOE/восстановленных PNG8. Global SSIM/policy — явная командная convention. Проверь именно этот вариант, не разрабатывай новый контракт с нуля. Ссылка https://github.com/NinjaMoons/nuclear-doe-2026/pull/15 ; приватный файл может быть недоступен, перечисленного описания достаточно для постановки.

Предлагаемые формы: targets [B,4,1,128,128], phi [B,1,128,128]. Это инженерный проект интерфейса, не повод менять общий контракт самостоятельно. PyTorch, CPU для коротких проверок; GPU-бюджет неизвестен. Рабочий предел времени — хакатон, точный срок кейса отдельно. Не обещай часы обучения/ускорение без замеров.

Не повторяй R-001: API/лицензии библиотек уже аудируются; ASM не является обязательным forward. Не ищи заново HoloNet или десятки архитектур. Если твоё прежнее исследование уже содержит релевантный loss — укажи его и закрой только оставшийся пробел.

## Нужный ответ
1. Укажи, чем пользовался и что реально выполнял; если нет веба/кода — явно сообщи.
2. Критика предложенного v1 и одно минимальное решение: точная формула ell, нормировки/веса по плоскостям и входной амплитуды. Разбери max-нормировку, её зависимость от prediction и градиенты вблизи равных максимумов. Не заменяй max на sum без доказанной практической причины. Раздели математические факты, решения и гипотезы. Объясни, что делаем с нулевыми/константными целями, brightness и различием output area. Не меняй яркость независимо от prediction для искусственного улучшения метрик.
3. Покажи общий computational graph four-targets -> сеть -> одна phi -> четыре обязательных forward -> один loss. Какой минимальный four-channel UNet подходит без изменения рабочего кода; не четыре независимых выхода phase.
4. Минимальный тест: поочерёдно включить только один из четырёх loss, убедиться в влиянии на одну phi; gradient total равен сумме градиентов; общий batch/plane порядок не перепутан. Отдельный тест ненулевых finite gradients сети. Код/псевдокод и expected, без придуманных логов.
5. Как сравнить один shared-phase Adam и neural inference на held-out наборах четвёрок при одинаковом forward/metrics; training time и inference отдельно. Проверь сохранённую PNG8-фазу отдельным прогоном, не только continuous phi.
6. До трёх первичных работ/исходников с URL/DOI/commit, которые действительно подтверждают метод, и условия заимствования кода/весов, если предлагаешь их. Неизвестное оставь неизвестным.
7. Таблица claim/status/evidence/action: CONFIRMED, PLAUSIBLE, REJECTED, NEEDS_TEST. Укажи одну рекомендацию для #3/#5 и вопросы для согласования с координатором/#4.

## Полезность
Разработчик может проверить предложенный общий loss и training smoke без фазовых labels и без повторного выбора библиотеки. Не обещай точное воспроизведение произвольных четырёх картинок одной фазой. Качество/сходимость остаются NEEDS_TEST до эксперимента.
