# Межмодульный контракт v0 (legacy / ASM)

**Официальный кейс требует v1:** [четыре плоскости и single-FFT Fresnel](INTERFACES_V1.md). Ниже сохранён v0 для ASM; он не считается конкурсным решением. Публичные v0-типы/сигнатуры не меняются.

Статус: предложение в инфраструктурном PR. После согласования Павлом и слияния этот commit становится базовым контрактом агентов. Полное ТЗ пока не получено; конкурсные параметры и достаточность одноплоскостной модели требуют проверки. Ниже — инженерные решения для минимального одноплоскостного фазового ДОЭ, а не требования организаторов. Многоплоскостность/3D, реальные параметры оптики, ограничения данных и формат сдачи определяются полным ТЗ. При необходимости изменить контракт ДО старта исполнителей.

## Общие типы
Стек инфраструктуры: Python 3.11+; CI — Python 3.11. Научный стек для будущих модулей: PyTorch 2.9.0 CPU, NumPy 2.3.4; тесты — pytest 8.4.2. Версии закреплены в requirements*.txt. Научные зависимости устанавливаются в CI только после появления научного кода; их вычислительная проверка ещё предстоит. CUDA — отдельная опция, не часть этого PR. Общие типы принадлежат координатору: `doe_core/contracts.py`; `__init__.py`, зависимости и общий конфиг также меняет координатор.

`OpticsConfig`: immutable dataclass с `wavelength_m: float` (длина волны в однородной среде), `pixel_pitch_m: tuple[float,float]` (dy, dx), `distance_m: float`, `pad_factor: int = 1`. Все длины в метрах; wavelength/pitch конечны и >0, distance конечна и >=0, pad_factor — положительный int. Индекс среды и вакуумная длина волны не подменяют wavelength_m молча.

Форма всех изображений/фаз/амплитуд: `[B,1,H,W]`, B>=1, H,W>=2; фаза в радианах. Реальные float32/64; соответствующие комплексные complex64/128. Преобразования не меняют device/dtype молча. NaN/Inf, неверные формы и несовместимые размеры — ValueError. Реализация должна сохранять autograd.

`SynthesisResult`: phase_rad (реальная фаза той же формы, итог в [-pi,pi)), intensity (сырая неотрицательная интенсивность на выходной плоскости), loss_history (list[float], включая исходный loss), elapsed_s (float>=0), metadata (JSON-совместимый dict: method, seed, config, device, dtype). В общем dataclass эти поля типизированы; проверку тензоров и результата выполняет владелец алгоритма, чтобы не импортировать torch в инфраструктурных проверках. Не возвращать PNG вместо численного результата.

## doe_core/asm.py
```python
def propagate(field: Tensor, config: OpticsConfig) -> Tensor: ...
def intensity(field: Tensor) -> Tensor: ...
```
`field` комплексный [B,1,H,W], результат той же формы. intensity = abs(field)**2, без нормировки. z=0 возвращает исходное поле (включая высокочастотные компоненты).

Соглашение для положительного z: exp(+i*kz*z), unshifted fftfreq, fft2/ifft2 по (-2,-1), norm='ortho'. Transfer H=exp(i*2*pi*z*sqrt(1/lambda^2-fx^2-fy^2)); ветвь корня Im>=0, эванесцентные компоненты затухают при z>0. Не использовать вещественный sqrt отрицательного числа или неявное abs внутри корня.

pad_factor=1 моделирует периодическую дискретную область. При >1 поле дополняется нулями симметрично до factor*H,W и после распространения вырезается исходное центральное окно; нечётный остаток идёт снизу/справа. Pitch сохраняется. Проверка полной мощности допустима для периодической области с распространяющимся спектром; после crop/затухания она не обязана сохраняться.

Одна формула FFT не доказывает корректность для любых z/pitch. Проверить sampling и сходимость с padding для выбранных конкурсных параметров; параметры с неподтверждённым aliasing не использовать в отчётных сравнениях. Band-limited ASM добавлять отдельным решением после оценки необходимости и согласования интерфейса. Основание проблемы дискретизации: Matsushima & Shimobaba, Optics Express 17, 19662–19673 (2009), https://doi.org/10.1364/OE.17.019662 ; авторский текст: https://kansai-u.repo.nii.ac.jp/record/11127/files/KU-1100-20091015-50.pdf . Это научная ссылка, не ТЗ хакатона.

## doe_models/adam.py
```python
def synthesize_adam(target: Tensor, config: OpticsConfig, *,
    propagate_fn: Callable[[Tensor, OpticsConfig], Tensor],
    steps: int = 100, lr: float = 0.05, seed: int = 0) -> SynthesisResult: ...
```
Target — интенсивность, конечная, >=0, положительная сумма каждого примера. steps>=1, lr>0. Алгоритм оптимизирует только вещественную фазу; входное поле `exp(i*phase)/sqrt(H*W)` — единичная мощность на пример. Фаза при обучении не зажимается; wrap только при возврате. Initial phase генерируется локальным generator(seed), без неявной смены глобального RNG.

Loss = mean((I/sum(I)-T/sum(T))**2) по B,C,H,W; если сумма предсказанной интенсивности <=1e-12 — явная ошибка, а не скрытая нормировка нулевого поля. Возврат лучшего состояния, включая начальное; intensity заново вычисляется для возвращённой phase. elapsed включает собственную оптимизацию и итоговый forward; CUDA синхронизируется при измерениях. Реализацию можно начать через внедрённый тестовый differentiable propagator, но интеграционная приёмка требует настоящего проверенного ASM.

## doe_experiments/data.py, metrics.py
```python
def make_targets(*, count: int, height: int, width: int,
                 seed: int) -> Tensor: ...
def evaluate(prediction: Tensor, target: Tensor, *,
             roi: Tensor | None = None) -> dict[str, float]: ...
```
Данные — неотрицательные интенсивности с единичной суммой, генерация seed-local, без скачивания внешних наборов. Разделение train/val/test по ID/seed ДО генерации baseline-labels; один объект не попадает в разные выборки.

Метрики независимо от core/models: normalized MSE (как выше), cosine_similarity между нормированными векторами, efficiency = sum(raw_I*roi)/sum(raw_I). Эффективность — доля мощности внутри наблюдаемого выходного окна, не полная оптическая эффективность, когда crop теряет энергию. ROI — bool той же формы, по умолчанию target>=0.1*max(target) на пример; пустой явный ROI запрещён. Усреднение per-sample метрик по B. Для одинаковых ненулевых изображений MSE=0, cosine=1; нулевые/невалидные примеры отклоняются. Время измеряется runner, не выдумывается evaluate.

## doe_models/unet.py, train.py
`PhaseUNet.forward(target: Tensor) -> Tensor` возвращает фазу [B,1,H,W] в радианах, сохраняет spatial shape, включая некратные степени 2 размеры. Пайплайн обучения использует тот же физический forward/loss. Обучение без supervised labels — допустимая минимальная гипотеза; если ТЗ требует пары, согласовать train loader без изменения core.

## Артефакты и UI
Runner сохраняет run.json: schema_version=1, git_sha, method, seed, config, shape, dtype, device, dependencies, metrics, steps, elapsed_s, timing_scope, checkpoint_sha256 (если есть), target_id, split. Численные target/phase/intensity — отдельный .npz, без pickle. JSON без NaN/Inf. Порядок train time, model load, warmup, synthesis и IO в timing_scope задаётся явно; speedup только при одинаковых hardware, target/config/precision и сопоставимом качестве.

UI вызывает публичные функции, показывает target/phase/intensity/метрики/время/параметры и происхождение checkpoint. UI не реализует собственный ASM или нормировку. Большие данные/веса/артефакты не коммитятся в git; для передачи использовать согласованное хранилище или Release assets, с размерами и SHA256.

## Общие импорты и точные ключи
Общие runtime-типы и Protocol: `from doe_core.contracts import OpticsConfig, SynthesisResult, Propagator`. `Tensor` — `torch.Tensor`, импортируется только в реализации/TYPE_CHECKING. `Propagator.__call__(field, config)` соответствует propagate. `loss_history` — значения после последовательных шагов, первым идёт начальный loss; не монотонна обязательно. Контракт требует возврат лучшего состояния, а не последний шаг. `metadata["config"]` — JSON-совместимый результат dataclasses.asdict(config), tuple превращается в JSON list при сериализации.

evaluate возвращает ровно ключи `normalized_mse`, `cosine_similarity`, `roi_efficiency`; каждый Python float — среднее per-sample. Значение `normalized_mse` совпадает с batch loss Adam (среднее по одинаковым H,W). ROI непустой на каждом примере. Для count/height/width/seed — Python int; count>=1, height,width>=2, seed>=0, bool вместо int не принимается. Генератор возвращает CPU float32, перенос на device и float64 делает вызывающий код явно. seed у Adam также неотрицательный int. Входной target Adam/model должен быть float32/64, обучающий код нормирует каждый пример перед подачей в модель согласно общему loss.

Один batch оптимизируется единой средней loss, лучшее состояние выбирается по этому среднему для всего batch. Автоматическое разрешение зависимостей или установка пакетов из алгоритмов запрещены. Научные ограничения и вопросы организаторам отслеживаются в инфраструктурной Issue, а не маскируются заглушками.
