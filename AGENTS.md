# Правила агентов Nuclear DOE

GitHub — единственный источник назначений, состояния задач, согласований и результатов. Перед каждым новым поручением читать актуальные Issue/PR, точные HEAD, CI, review и ACK владельцев. Старые комментарии и локальная память не заменяют текущие подтверждённые сведения. Если источники противоречат друг другу, зафиксировать расхождение и предложить минимальную правку; владельцев без подтверждения Павла не менять.

Для обязательного кейса читать свою Issue, docs/INTERFACES_V1.md и docs/COORDINATION.md. docs/INTERFACES.md описывает legacy v0/ASM и не заменяет v1.1. В main может оставаться инфраструктура до согласованного merge: продолжать существующую рабочую ветку/PR из своей Issue, не создавать её повторно и не начинать готовый модуль заново. Новый незанятый этап начинает ветку от указанного проверенного интеграционного HEAD.

Кейс: четыре amplitude targets [B,4,1,128,128] -> одна phase [B,1,128,128] -> complex single-FFT Fresnel на четырёх z. Все физические единицы SI, фаза в радианах. PRIMARY A=abs(U), I=A.square() только для диагностики/мощности. PNG/255 уже amplitude, без sqrt. Финальные Pearson/SSIM — после DOE.png/reload ->4Fresnel ->4PNG/reload. Общие сигнатуры и политика задаются v1.1; экспериментальный training objective допускается только явно согласованным opt-in в Issue с отдельной provenance, без скрытой смены default/display/evaluation.

Один файл — один владелец изменений. Общие contracts, __init__, зависимости, workflow и общая документация принадлежат координатору. Не менять чужие файлы/ветки; не делать force push. Один исполнитель — одна ACTIVE и явные READY NEXT/BLOCKED. После завершения этапа обновлять очередь. Независимые ревьюеры проверяют, а не параллельно реализуют чужие модули.

Перед PR выполнять проверки, относящиеся к изменениям; указывать exact HEAD, команды, результаты и пропуски. Не повторять аудит неизменённого кода. Обязательные независимый physics gate и настоящий DATA gate должны пройти на одном точном интеграционном tree; missing dependencies дают FAIL, не skip/stub. Module READY, Adam baseline, реально обученная сеть и полная конкурсная приёмка — разные состояния. Трёхшаговый smoke не является проектным обучением; NN speedup требует парного benchmark.

Не выполнять merge или финальную сдачу без проверок и необходимых согласований. Не запускать платные API/вычисления, опасные команды, длительное/GPU обучение или большие загрузки без разрешения. Датасеты/checkpoints/generated artifacts вне обычных git commits, с hashes/provenance. Foundation AI и nuclearhack-transcriber не затрагивать.

До дедлайна P0: рабочий E2E, корпус для обучения, trained checkpoint, настоящий held-out inference, обязательные артефакты и сдача. P1: парный benchmark, научная/техническая приёмка, воспроизводимость и демонстрация. P2: необязательные улучшения/эксперименты. #4B не ждёт #5B, #5B не ждёт #6B. Не позволять приёмке готового collector или косметическим замечаниям блокировать корпус/обучение. После разрешённого короткого этапа переходить к READY NEXT по условиям своей Issue без нового ручного технического промпта Павла.
